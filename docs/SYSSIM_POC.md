# 分布式系统自愈 PoC

一个去中心化调度系统的故障韧性验证：节点通过共享环境信号自主协调，
没有中心调度器。

## 模型

### 节点

每个节点有：
- **健康度** `health ∈ [0,1]`：1 = 健康，0 = 失效
- **负载** `load ∈ [0,1]`：当前承担的负载比例
- **容量** `capacity`：最大处理能力（异质，对数正态分布）

### 任务

持续到达，每个任务有固定需求量（默认 10）。系统必须持续处理，
而不是「跑完就结束」——这才是真实系统的负载模式。

### 环境信号（stigmergy 载体）

两个通道：
- `load_signal`（衰减 0.90，扩散 0.10）：节点广播自己的负载
- `health_signal`（衰减 0.95，扩散 0.05）：节点广播自己的健康度

节点只读**邻域**信号，没有全局视图。

## 两种协调策略

### 去中心化

每个 tick，每个健康节点：
1. 读自己邻域的平均负载
2. 如果自己比邻域空闲 → 从未分配队列抢若干任务
3. 如果自己比邻域忙 → 释放一个任务回队列
4. 处理持有的任务

**关键**：没有调度器，没有全局状态，决策完全局部。

### 中心化（对照组）

中心调度器：
1. 收集所有健康节点的吞吐能力
2. 按能力排序，轮询分配未分配任务
3. 下发

**弱点**：中心失效后停止调度。

## 实验结果

### 多种子统计（10 seeds，1000 节点，300 ticks）

| 场景 | 去中心化 | 中心化 | 差异 |
|---|---|---|---|
| 正常运行 | 93.5% ± 4.1% | 87.7% ± 1.4% | **+5.8pp** |
| 中心失效 | 93.5% ± 4.1% | 51.1% ± 0.0% | **+42.4pp** |
| 节点故障 | 92.8% ± 4.7% | 86.1% ± 1.5% | +6.8pp |
| 失效 + 故障 | 92.8% ± 4.7% | 50.3% ± 0.4% | **+42.6pp** |

**两个发现**：

1. **正常运行时去中心化反而更好**（93.5% vs 87.7%）。
   原因：中心化调度器按顺序轮询分配，导致任务等待；
   去中心化节点主动抢单，响应更快。

2. **中心失效后差距 42 个百分点**。中心化方案在中心死掉瞬间
   停止调度，完成率永久卡在半数；去中心化不受影响。

### 规模扩展（中心在 tick 50 失效，50 ticks）

| 节点数 | 耗时 | 去中心化 | 中心化（失效） | 差异 |
|---|---|---|---|---|
| 10,000 | 0.12s | 76.3% | 29.6% | +46.6pp |
| 25,000 | 0.30s | 76.6% | 16.2% | +60.3pp |
| 50,000 | 0.71s | 75.9% | 9.6% | +66.3pp |
| 100,000 | **1.63s** | **76.0%** | **5.4%** | **+70.6pp** |

**核心结果：去中心化性能在 10 倍规模扩展下完全不变（76.3% → 76.0%），
而中心化从 29.6% 崩到 5.4%。**

原因很直接：中心失效后，中心化方案不再分配任何新任务，
只有已分配的任务被处理完，所以完成率随规模增大而趋近于零
（任务池是 O(n) 增长的，而中心一旦死亡就不再调度）。
去中心化方案没有这个问题，因为每个节点独立决策。

## 复现

    cd rust
    cargo build --release
    ./target/release/shi syssim      # 四个场景对比
    cargo run --release --bin stats -p shi-syssim   # 多种子统计 + 规模扩展
    cargo run --release --bin bigscale -p shi-syssim  # 超大规规模

## 局限与诚实的说明

1. **这是仿真，不是真实系统。** 没有网络延迟、没有一致性问题、
   没有真实的任务语义。环境信号是「完美共享内存」，真实系统里
   需要分布式状态同步（gossip / CRDT）。
2. **中心化对照是简化的。** 真实的 K8s 有多个 control plane 副本、
   leader 选举、故障转移。这里的「中心」是单点且无备份，
   所以它失效后的表现比真实系统差。
3. **任务模型是抽象的。** 真实任务有依赖、有时限、有优先级。
   这里所有任务等价。
4. **去中心化的「抢单」有竞争风险。** 当前实现里，多个节点可能
   同时从队列取同一批任务（虽然用 VecDeque 避免了重复分配，
   但真实分布式系统需要分布式锁或 CAS）。
