协调介质的能力边界

无中心系统的一组定量定律

研究报告 · 2026-11-28

全部实验可复现：git clone 后 cargo run --release --bin <实验名>

代码量：Rust 约 5000 行，85 个测试，跨机器确定性验证通过

摘要

无中心系统（蜂群、集群、多智能体）靠共享介质协调：信息素、标记、共享内存、消息板。

它们看起来千差万别，但受同一组约束支配。

本研究用确定性仿真框架，在四个不同场景里定量测量了这些约束，得到四条定律：

定律一句话最强证据
一、容量性能上限由介质的信息容量决定，不由个体的智能决定个体复杂度效应量 d = -0.84（有害）
二、对齐约束若不与信号同向，会破坏而非增强协调加约束后性能从 0.926 崩到 0.209（-77%）
三、密度通信受限时，扩大规模会让系统变差40 架 21.2% → 320 架 10.0%
四、污染伪造信息比删除信息更致命；只有能区分真假的防御才有效注入 -43.8pp vs 干扰 -25.6pp；快速衰减净损 27pp

第四条在多智能体共享记忆系统里独立验证成立：

15% 的 agent 被劫持导致 43.5 个百分点的性能损失，

而溯源认证恢复 100%，代价为零。

贯穿四条定律的统一判断：

无中心系统的能力，是它协调介质的属性的函数——而不是它组成部分的智能的函数。

这条判断与当前「给每个节点装更强的智能」的主流方向相反。

一、问题与方法

1.1 为什么问这个问题

无中心系统在三个地方被大量使用：蜂群机器人、分布式集群、多智能体 AI。

三者的工程实践各自演进，但很少互相引用。

它们共享同一个数学结构：

  • 个体只感知局部
  • 协调靠改变/读取共享介质（stigmergy）
  • 没有一个组件持有全局状态

如果这个结构是本质的，那么它们的能力边界应该由同样的因素决定。

1.2 方法：确定性仿真 + 对照实验

核心要求是可复现。 涌现行为对初始条件敏感，浮点实现的微小差异会导致完全不同的宏观行为。

不加约束的仿真实验，结论不可信。

框架的三条硬约束：

  1. 固定时间步长，不用真实时间
  2. 独立随机流：每个个体从主种子派生自己的流，禁止全局 RNG
  3. 状态哈希：每 N tick 对全状态做 FNV-1a 哈希

验证结果：

检查结果
同种子 100 次运行哈希序列 100% 一致
本地 Windows vs 远程 Linux哈希逐位一致
Rust 内核 vs Python 原型算法对齐（后者用于快速验证）

实现：Rust，100,000 个体 × 1,000 tick = 1.63 秒（37M agent-ticks/s）。

1.3 四个场景

场景介质对应现实
延迟觅食多通道信息素需要记忆的协作任务
目标聚集势能场环境塑造与目标注入
分布式调度共享状态场集群任务分配
蜂群攻击有限信道标记通信受限的多机协同
多智能体共享记忆板LLM agent 协作

二、定律一：容量

系统的性能上限由协调介质的信息容量决定，个体智能无法突破这个上限——在容量充足时，个体智能甚至有害。

2.1 实验设计

任务：延迟觅食。资源只在「侦察窗口」可见、「采集窗口」可采，两窗口不重叠。

个体没有记忆（硬编码约束），唯一的信息载体是环境。

双因素设计：

  • 因子 A（介质容量）：通道数 1 / 2 / 4 / 8
  • 因子 B（个体复杂度）：简单（1 条规则）/ 中等（3 条）/ 复杂（10 条 + 自适应）

控制变量：8 种资源类型。通道数 < 类型数时必然发生类型混淆。

2.2 结果

采集效率（10 次重复）：

通道数 \ 复杂度简单中等复杂
156.4%56.4%56.4%
272.3%72.5%66.9%
481.0%79.8%66.1%
880.9%81.0%70.2%

效应量：

  • 环境容量：d = 3.26（大效应）
  • 个体复杂度：d = -0.84（负效应）

2.3 三个推论

推论 1：容量存在「够用」阈值。

通道 1→4 提升 24.6 个百分点；4→8 只提升 -0.1 个百分点。

本实验中阈值 = 4，正好是资源类型数（8）的一半。

推论 2：智能无法弥补容量不足。

通道 1 时三个复杂度等级结果完全相同（56.4%）。

信息不存在时，再聪明的处理也无济于事。

推论 3：容量充足时，智能有害。

通道 4 时，复杂度 3 比复杂度 1 差 14.9 个百分点。

原因：环境已提供协调所需信息，个体额外的内部处理只引入噪声和延迟。

2.4 理论锚点

这印证了 Conant–Ashby 良好调节器定理（1970）：

任何好的调节器都必须是系统的模型。

无中枢约束说：模型不能放在任何个体里。

两条约束的交点只有一个解：把模型放进环境。

三、定律二：对齐

约束本身无害，与信号冲突的约束才致命。

3.1 背景：目标注入

问题：给定固定的个体规则，能否通过塑造环境把系统吸引子移到指定位置？

三个塑造方法（个体规则固定为纯梯度跟随）：

方法聚集度改善
不塑造0.106 ± 0.0110.5%
势能景观0.929 ± 0.00296.7%
边界条件0.105 ± 0.0110.0%
反馈通道0.929 ± 0.00296.7%

边界条件完全无效。 个体被墙挡住后只会沿墙滑动，不会主动找出口。

3.2 更严重的发现：约束会破坏已有的引导

把势能场和边界叠加：

配置聚集度平均距离
只有势能场0.9260.77
势能场 + 边界0.20915.66

加边界让性能从 0.926 崩到 0.209（-77%）。

机制：个体沿梯度朝目标移动 → 撞上环墙 → 梯度仍指向目标（穿过墙）→

在墙边反复尝试无法前进 → 永久卡住。

这不是「边界不够强」，是结构性冲突：梯度说「往这边走」，边界说「不能走」。

3.3 但是对齐的约束几乎无损

只在梯度接近零的地方放边界（个体本来也不会主动去）：

边界密度冲突边界对齐边界差异
1.3%0.5750.929+0.354
3.9%0.3460.786+0.440
7.6%0.2270.786+0.560

同样密度下，对齐边界的性能高 0.35–0.56，且密度越高优势越大。

3.4 可操作的设计规则

加约束前，先检查该处的信号梯度强度。

- 梯度强 → 不要加约束（会冲突，系统卡死）

- 梯度弱 → 可以加约束（安全，几乎无损）

真实系统对应：调度器说「往 A 扩容」时，不要设置阻止扩容的配额。

只有在「没有明确方向」的地方才用规则约束。

四、定律三：密度

通信受限时，扩大规模会让系统变差；存在一个最优规模。

4.1 实验设计

蜂群攻击场景：80 架无人机、20 个目标、战场 200×200、无指挥所。

无人机通过有限信道的共享标记协调（发现目标→写标记→其他无人机跟随）。

4.2 通信容量决定覆盖率

信道 1→20 提升 47.5 个百分点；≥ 目标数（20）后完全饱和。

通信充足时，无人机越多越好（160 架就 100% 覆盖）。

通信瓶颈时，40 架最好，加到 320 架反而掉到 10%。

机制：信道不足 → 多个目标抢同一信道 → 信道归属被最后一个发现者覆盖 →

所有无人机被导向同一个目标 → 规模越大扎堆越严重。

「更多无人机 = 更强蜂群」这个直觉是错的。

通信越差，指挥所越不可替代。 反过来：通信够好，去中心化就够了。

五、定律四：污染

伪造信息比删除信息更致命。而只有能区分真假的防御才有效。

5.1 四种攻击的分类学

当攻击者能写入协调介质时，有四种攻击方式：

攻击机制本质
拒绝 Denial压制信道删除信息
注入 Injection随机位置写假标记伪造信息
重放 Replay已摧毁/虚假位置重写伪造过期真相
淹没 Flooding高频随机噪声稀释信息

5.2 结果（基准 85.5%，等预算对比）

攻击覆盖率损失
注入（2 标记/tick）42.0% ± 10.6-43.5pp
淹没（2 标记/tick）40.5% ± 20.3-45.0pp
拒绝（压制 50% 信道）61.0% ± 9.9-24.5pp
重放（时间对齐）72.0% ± 8.2-13.5pp

伪造/稀释信息的伤害是删除的 1.7–1.8 倍。

机制：

  • 删除 → 无人机失去引导，退化为随机搜索。低效，但不会主动犯错
  • 伪造 → 无人机被主动引向错误位置，付出真实的飞行和弹药成本

5.3 一个被推翻的假设

初版测出重放只有 -11.5pp。我假设是时间混淆（重放要等目标被摧毁才有诱饵）。

做了时间对齐实验（预设幽灵位置，tick 0 生效）：只改善 2 个百分点。

假设错了。 真正的机制是诱饵分布：

固定位置的诱饵只能捕获经过附近的无人机；

随机分布的诱饵能捕获任何位置的无人机。

工程含义：防御重放只需校验少数已知位置；防御随机注入需要全通道认证——

后者成本高得多。

5.4 防御评估：便宜防御比攻击更贵

防御攻击下收益无攻击时代价净效果
溯源认证+45.0pp（恢复 100%）0压倒性正
快速衰减 0.99+1.9pp（恢复 4%）-1.9pp≈0
快速衰减 0.95+3.1pp（恢复 7%）-33.8pp净损 27pp
快速衰减 0.90+1.9pp（恢复 4%）-40.0pp严重负

「缩短标记寿命」这种显然的抗攻击手段，净损失 27 个百分点。

原因：真假标记共用同一个衰减通道。削弱假标记的同时也破坏真标记——

而真标记需要活得足够长（无人机跨场要 200 tick）。

5.5 跨域验证：多智能体共享记忆

为什么能跨域：当前主流的多智能体 LLM 架构里，agent 通过共享记忆/消息板协作

（完成子任务→写「我做完了」→其他 agent 读到后跳过）。这和蜂群的标记场结构完全相同。

攻击模型：被劫持的 agent 往共享记忆写假完成记录。

5.6 统一规律

把两个系统的防御结果放在一起：

防御类型蜂群多智能体无攻击代价
溯源认证（区分真假）恢复 100%恢复 100%0
交叉验证（区分真假）未测恢复 90%0
快速衰减（削弱一切）净损 27pp——

防御是否有效，取决于它能否区分真假信号，而不是它削弱了多少信号。

六、一个反向的对照：分布式调度里 HA 抹平了优势

在把「无中心」当卖点时，我做过一个分布式调度的对照实验。

初版结果看起来很好：无中心方案在中心失效后领先 42 个百分点。

但那是对着稻草人测的——对照组是单点、无备份的中心。

加入真实的 HA control plane（3 副本 + 选主）后：

配置完成率说明
去中心化（无故障）95.6%基线
去中心化（中心失效）95.6%不受影响
中心化单副本（无故障）87.5%基线
中心化单副本（中心失效）51.4%停止调度
中心化 3 副本 HA（无故障）87.5%基线
中心化 3 副本 HA（leader 失效）87.3%选举后恢复

HA 几乎完全抹平了故障韧性差距。公平的差距是 +8.3pp，不是 +42pp。

这一节的教训和方法论价值大于结论本身：任何「某方案在某维度更优」的结论，

必须先确认对照组是强的，不是随意搭的。

七、方法论反思：我在这个项目里犯的错

这一节记录模型缺陷如何伪装成科学结论。它们是研究过程的一部分。

7.1 缺陷伪装成结论的案例

现象初步结论真实原因
三种塑造方法都 100% 完成「任务很简单」资源在窗口内直接可见，个体不需要记忆
信道数完全不影响结果「信道不重要」标记衰减半衰期 14 tick，无人机跨场要 200 tick，标记先死了
边界条件 0% 改善「约束无效」边界阻挡了 94.5% 的格子，个体一开始就被冻住
三条攻击曲线完美重合「这些攻击无效」防御字段默认值是 1.0，所有攻击被拦截
淹没是最强攻击「噪声破坏力最大」我给淹没分配了 4 倍预算
无中心领先 42pp「无中心更抗故障」对照组是单点无备份，不是真实 HA

7.2 三条可复用的检查

检查 1：参数的时间尺度必须匹配现象。

标记寿命 < 飞行时间 → 标记无效。这类错误不会报错，只会给出「无效应」的假结论。

检查 2：失败模式必须有代价。

初版让无人机「就近攻击」，走到哪里都能顺手打一个，

于是「跑错地方」免费——协调失败不可见。改成承诺式攻击后才测出差异。

检查 3：分类学实验必须等预算归一化。

给一种攻击 4 倍预算，它自然看起来最强。所有对比都必须在同等资源下进行。

7.3 一句话

第一次扫描结果平坦时，第一反应应该是「我的模型制造出想要的现象了吗」，

而不是「假设被证伪」。

这个项目里，五次平坦结果中有四次是模型缺陷。

八、边界与局限

诚实地列出这套结论不覆盖的地方。

8.1 建模层面的局限

局限影响
网络延迟是离散 tick 模型，不是连续时间真实系统的时序特性未覆盖
丢包用确定性哈希模拟无真实网络抖动
标记场是「归属覆盖」，无真实信号叠加干扰的物理过程被简化
目标静止侦察信息不会过期
无时钟同步时序协调（压制+突击同步）未建模
多智能体用规则 agent，不是真 LLM验证的是结构，不是 LLM 行为

8.2 理论层面的局限

  • 四条定律都是实验规律，不是定理。没有给出解析形式。
  • 容量阈值（如「通道数 ≥ 目标数」）是否普适，只在一个任务里验证过。
  • 「密度反噬」的最优点位置（40 架）依赖具体参数，没有归一化公式。

8.3 未触碰的问题

研究纲要里列过三个结构性缺陷，本项目一个都没解决：

缺陷状态
长程规划纯反应式系统没有「未来」变量，未建模
信用分配无法归因个体贡献，未处理
对抗性博弈攻击者与防御者都是固定策略，无学习

九、应用含义

9.1 四条可直接使用的规则

场景规则依据
系统设计先投资介质容量，再投资节点智能定律一（d=3.26 vs -0.84）
策略配置约束前先看信号梯度，梯度强处不加约束定律二（-77% 崩塌）
规模规划通信受限时不要扩容，先扩信道定律三（320 架 10%）
安全设计优先做溯源认证，不要用「普遍削弱」式防御定律四（认证恢复 100%，衰减净损 27pp）

9.2 四条定律的适用边界

这些结论适用于：

  • 个体只感知局部
  • 协调靠共享介质
  • 个体规则不可任意修改

不适用于：

  • 有中心调度且中心可靠
  • 需要长程规划
  • 强对抗博弈（双方会学习）

十一、未解决的问题

如果继续，这些问题更值得投入：

  1. 四条定律的解析形式。现在全是实验曲线，没有公式。

容量阈值能否用任务结构（类型数、目标数）推导出来？

  1. 真实 LLM 验证。multimem 用的是规则 agent。

把决策函数换成 LLM 调用即可验证，但需要 API 预算。

  1. 对抗性博弈。攻击者和防御者目前都是固定策略。

如果攻击者能学习（选择最优攻击类型与强度），结论会怎么变？

  1. 时序协调。压制与突击同步是无中心系统的硬约束，本项目完全没碰。
  1. 从仿真到真实系统。所有结论都在仿真里。真实蜂群/集群的验证需要硬件。

十二、结语

这个项目最初的问题是「为什么没有完全公平的大战场沙盘游戏」和

「昆虫没有脑子为什么能协作」。

一年实验下来，这两个问题收敛成同一件事：

一个系统能达到什么，取决于它的组成部分之间能共享多少真实信息——

而不取决于每个组成部分有多聪明。

四条定律是这句话在四个维度上的量化：

  • 容量：共享多少 → 决定上限
  • 对齐：共享的信号和控制是否同向 → 决定能否落地
  • 密度：单位介质承载多少 → 决定规模
  • 污染：共享的是不是真的 → 决定安全

而贯穿始终的方法是同一个：确定性仿真 + 强对照 + 诚实的自我修正。

本项目所有代码、数据、实验脚本均开源。

Rust 约 5000 行，85 个测试，跨机器确定性验证通过。
